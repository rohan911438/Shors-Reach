THE PROJECT
-------------------------------------------------------------------------------------

Name:
Shor's Reach

Tagline:
See your crypto the way a quantum attacker sees it — then lock your QoreChain account before they can.

Category:
Quantum Pass

Description:
About 6.3 million BTC (roughly 31% of supply) already sits behind public keys that are visible on-chain. A large enough quantum computer running Shor's algorithm could derive the private keys for those coins. Most holders have no idea whether they are exposed, because address checkers look at one address while the real risk belongs to the key: the same key shows up in seven Bitcoin address forms, on every EVM chain, and in Satoshi-era outputs that have no address at all.

Shor's Reach shows you what a quantum attacker would see. Paste a Bitcoin address, public key or xpub, any 0x address, or a qor1 address. The scanner runs in your browser and checks the key, not just the address, across Bitcoin, 7 EVM chains and QoreChain. Each holding gets a clear verdict (Exposed now, Exposed on spend, PQ-protected, or Unknown) with its value in BTC and USD. Every red verdict links to the exact transaction that revealed the key; if there is no proof, it is never marked red. It catches what simpler tools miss: raw-key P2PK coins, Taproot, reused keys across address types and chains, Safe owners and EIP-7702 delegations.

An AI advisor (Google Gemini) turns the results into a calm, step-by-step plan, and you can ask follow-up questions. It only sees an anonymised summary, never your addresses, and you can see exactly what was sent.

Then fix the part you can fix today: QoreChain. Shor's Reach checks whether your QoreChain account has a registered ML-DSA-87 post-quantum key and whether an EVM window leaves funds open to ECDSA. Once the account is protected, you mint a soulbound Quantum Pass. The contract verifies your ML-DSA-87 signature on-chain (or checks a hybrid secp256k1 + ML-DSA-87 transaction sent from QoreX) and binds the pass to your registered key.

You can also add addresses to a watchlist with Telegram alerts, share a card that contains no addresses, and use the public Scan API and embeddable widget for wallets and exchanges.

Short version (if the form limits the length):
Shor's Reach scans Bitcoin, 7 EVM chains and QoreChain at the key level — not the address — and shows what a quantum computer could attack today, with the transaction that proves each verdict. It catches what address checkers miss: Satoshi-era raw-key coins, Taproot, sibling address forms, cross-chain key reuse. An AI advisor turns it into a calm plan from an anonymised summary. Then you mint a soulbound Quantum Pass on QoreChain, proven by a hybrid secp256k1 + ML-DSA-87 transaction and bound to your registered post-quantum key.

How it's made:
ARCHITECTURE
- Scaffolded with create-qorechain-dapp: the viem-wagmi template (Vite, React, wagmi, RainbowKit + QoreX) for the app and the foundry template for contracts. The first commit is the untouched scaffold.
- Scan engine (TypeScript, runs in the browser, no addresses stored server-side): mempool.space / blockstream Esplora for Bitcoin, 7 public EVM RPCs, QoreChain REST (PQC account status + EVM window), CoinGecko for USD value. For each key it derives all 7 sibling forms (P2PK c/u, P2PKH c/u, P2WPKH, P2SH-P2WPKH, BIP-86 Taproot), finds raw-key P2PK outputs by script hash, scans xpubs to the gap limit, and applies the cross-chain EVM rule, Safe owners and EIP-7702. Invariant: every "Exposed now" verdict links to the transaction that revealed the key; no evidence means it is downgraded to "Unknown".
- QuantumPass.sol: a soulbound pass (ERC-5192). mint() verifies an ML-DSA-87 signature on-chain with the pqcVerify precompile (0x0a01) against the key returned by pqcKeyStatus (0x0a02). attest() is the QoreX path: the user's proof is a hybrid-signed native self-transfer whose memo commits to the pass; our /api/attest checks it, the contract re-checks the registry and burns the proof so it can't be reused.
- QoreChain account check: is an ML-DSA-87 key registered, is an EVM window open, and how much could an attacker move if ECDSA broke tomorrow.
- AI advisor + "Ask about your plan": Google Gemini (gemini-3.5-flash) with structured JSON output, zod validation in and out, filters that block addresses and seed phrases before any model call, and a deterministic rule-based fallback. Users can see exactly what was sent.
- Extras: watchlist with Telegram alerts (@ShorsReachBot), public counter + share card (no addresses), Scan API (POST /api/v1/scan) and an embeddable widget.
- Deployed on Vercel (frontend + serverless /api/advise, /api/attest). 113 app tests (Vitest) + 18 Foundry tests (fuzz + attack cases), CI on GitHub Actions.

KITS AND NETWORK FEATURES
- @qorechain/sdk: unified account, EthNativeSigner hybrid signing, openEvmWindowMsg, buildRegisterPqcKeyMsg, signProofOfPossession, pqcSign
- @qorechain/evm: evmWindowStatus, chain definitions
- @qorechain/qorex-rainbowkit + @qorechain/qorex-types: QoreX connect, native enable / getKey / signAndBroadcast
- Network: hybrid secp256k1 + ML-DSA-87 transactions, PQC key registration with proof of possession, EVM windows, Solidity pqcVerify (0x0a01) and pqcKeyStatus (0x0a02) precompiles

WHAT WAS HARD
- Exposure is a property of the key, not the address: one key appears in 7 Bitcoin forms and on every EVM chain, and Satoshi-era outputs have no address at all (found by script hash).
- Making the pass prove a real post-quantum key: verifying ML-DSA-87 inside Solidity via the precompile, and a second attest path for QoreX users whose proof is a hybrid native transaction.
- Keeping the AI useful but private: only an anonymised summary leaves the browser, with leak filters and a fallback when the model is down.

AI-NATIVE
Built with Claude Code through a gated P01→P13 plan; the AI usage is documented in AI_USAGE.md.
